# 部署安装与迁移边界

2026-10-11更新。源码包支持不含私人历史数据的空工作区首次启动；已核验历史演示与新论文检查仍需完整来源配置。历史收据包含旧 D 盘绝对路径，不能声称迁移到任意路径后全部检查立即可用。

## 运行环境

已验证Windows、Python 3.13。应用直接依赖固定在requirements-app.txt：lxml、openai、Pillow、PyMuPDF、python-docx、pydantic。requirements-nanobot.txt来自随项目源码的pyproject依赖：由于nanobot.agent初始化会导入AgentLoop，必须安装完整框架声明依赖及其传递依赖；不能声称仅6个包就可完整启动。nanobot源码随项目保存，bootstrap绑定本地源码路径；当前应用不启动或部署其聊天/channel代理。

初次安装：

```powershell
Set-Location -LiteralPath "项目完整路径"
powershell -NoProfile -ExecutionPolicy Bypass -File .\bootstrap.ps1
.\.venv\Scripts\python.exe -m pip check
.\.venv\Scripts\python.exe deployment_smoke.py --output output/deployment_smoke.json
.\.venv\Scripts\python.exe run_agent_ui.py --port 8787
```

浏览器访问http://127.0.0.1:8787/。前端发布目录web_frontend/dist已经构建时日常无需npm；需要修改前端时进入web_frontend执行npm ci、npm run build（需要Node/npm）。服务只监听本机。

如需断网安装，先在相同Python/操作系统平台下载依赖，再复制wheelhouse：

```powershell
python -m pip download -r requirements-app.txt --dest output/wheelhouse
powershell -NoProfile -ExecutionPolicy Bypass -File .\bootstrap.ps1 -Wheelhouse "轮子目录完整路径"
```

bootstrap用--no-index安装离线轮子。轮子是平台相关安装资产，Python/操作系统改变时需重新准备。部署验收venv与日常venv分开，不覆盖日常环境。

Windows Python 3.13会优先采用requirements-lock-win-py313.txt，锁定本次干净环境实际安装的全部运行依赖；其他Python版本使用requirements-app.txt及nanobot声明范围，需在目标平台重新验证和冻结。已实际生成源码ZIP并在另一目录解压、重新建立独立venv、完全--no-index安装，局部链与server/agent模块导入通过。源码包包含前端 src、构建配置、package-lock.json 及 web_frontend/dist/assets，不包含轮子、私有data、API配置或既有venv；wheelhouse需另行离线携带。

## 配置与密钥

将config.example.json复制为项目目录下的config.json，修改workcopy和svn_executable后启动。app_settings.py实际读取此文件（UTF-8，可带BOM），只接受上述两个本地路径且核验目录/文件存在，不写入或改动目标。也可用THESIS_WORKCOPY、THESIS_SVN_EXECUTABLE环境变量覆盖；未设置时兼容原D盘工作区与TortoiseSVN默认路径。禁止在config.json储存Key/密码/token，加载时拒绝密钥字段或未知设置。

端口实际由run_agent_ui.py --port设置；服务器Key由DEEPSEEK_API_KEY环境变量或网页当次输入读取，禁止把Key写进配置/报告/交付包。模型默认deepseek-flash；具体预算以网页和运行记录为准，默认16请求/60000保守token预留，硬上限24请求/80000。原生表三线表要求和分章要求必须明确确认才启用。

SVN自动采集需要可用svn命令行客户端和仓库读取凭据；只读Word分页/旧DOC转换需要Windows及Microsoft Word。纯 DOCX 解析和空工作区网页无需 API Key；使用教师规则检查论文须先配置并核验规则来源，真实语义和图片审阅另需 API。离线验收不证明模型审阅质量。

## 迁移资产与边界

应用源码、nanobot工具源码、web_frontend/dist以及对应数据目录要整体保留；哈希和收据不得改写来伪造原件。主服务ROOT从自身文件位置取得，但小批次历史工具、审定目录、manifest和历史收据部分仍使用绝对路径。可靠移迁有两种方式：在受信任同一目录D:\svn_agent复制已核验完整工作区，或另写明确的来源路径映射并逐条重核验，不能仅全文替换路径后宣称全部通过。

新机器不应复制旧.venv，使用bootstrap重建。不要把真实学生论文、姓名/学号、请求日志、API密钥提交到公开仓库；私有教学部署复制数据前应获得相应授权。只有本机预览不外发，选择Agent审阅会把必要原文/图片发给外部LLM供应商，正文匿名化及外发说明以当前实现为准。

deployment_smoke只检查合成DOCX→原文解析→局部检查→批注提取→工具注册→审定和注册空包，LLM/SVN/Word均0；不把它称为干净环境全仓真实API测试。真实模型、Word版面、SVN权限和历史按钮应在目标机器分别验证后再完成部署验收。

## 空工作区与严格核验

首次启动在缺少全部指定历史演示目录时返回空工作区，展示配置要求，不生成学生、论文、规则或检查结果。教师规则库显示实际为空；可执行检查数为 0。新论文上传、继续审阅与初稿核查会在任务受理前被阻止；因此“网页能启动”与“能按教师规则检查论文”是两个验收项目。

只要任一历史演示目录存在，就继续执行完整来源核验；缺失原件、哈希不符或不完整目录必须报错，不降级为正常空工作区。实验操作仅在完整同源证据就绪后提供。

配置 workcopy 与 svn_executable 后，可发现仓库论文、导出教师历史稿。现有检查器还绑定原始规则目录和批注证据；采集新仓库本身不会替换这项依赖。迁移前应由数据负责人确认授权，并按原目录关系迁移完整私人证据后重新核验。跨路径迁移需另行实现明确来源映射及逐项校验，目前没有通用规则导入按钮；不得修改哈希或伪造原件来完成配置。

正式移交应保存源码 ZIP、同版本清单、独立安装结果及网页首次启动记录。2026-10-11 发布采用新的日期命名和目录，保留旧发布包。清单逐文件 SHA256 必须与打包时源码一致；源代码变更后应创建新发布目录，不覆盖旧清单。

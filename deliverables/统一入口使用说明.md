# 论文检查项目统一入口

入口：[paper_pipeline.py](<D:/svn_agent/paper_pipeline.py>)；演示配置：[pipeline_demo.json](<D:/svn_agent/pipeline_demo.json>)。

## 已完成的整合

`replay` 从已验收三学生智能体运行重新核对原始工具证据、固定语境和视觉收据，生成一份交付报告及证据索引。本命令无需SVN、Word或模型API。它复用历史3020-token智能体结果，新增token为0。

`run --config` 按配置串联只读SVN导出、批注提取、单次模型候选归纳和学生稿线索检查，并在 `awaiting_rule_and_context_review` 状态停下。新候选规则没有自动启用；当前流程仍需批注语义、规则范围、学生版本身份及真实分页复核。因此它是可配置采集与检查线索入口，不是新样本完整自动判错系统。

旧版nanobot智能体及其报告保留。统一入口负责协调确定性的本地步骤，既有三学生检查使用nanobot受控工具与证据；新增候选归纳仅用一次DeepSeek请求，不需要不可控通用编码agent部署。

## P001演示：现在执行的命令

目录为 `D:\svn_agent`：

```powershell
.\.venv\Scripts\python.exe "D:\svn_agent\paper_pipeline.py" run --config "D:\svn_agent\pipeline_demo.json"
```

程序依次显示 `export`、`extract`、`candidates`、`check`。前两步无需LLM，候选归纳步骤才在本地读取API Key。最多请求1次，输出上限1600 token，输入材料最多12条符合条件的批注、按学生轮流选择，另限制请求字节数。不是严格总token预算；实际用量及未知用量写入账本，截断或失败不自动重试。

演示配置选择P001、snapshot502、教师mayy最近2份论文提交版本及学生r194明确路径。这属于已有学生重复试验，不是独立新样本。初稿身份字段暂为 `configured_student_version`，不凭版本号自动声称最早初稿。SVN提交者与批注作者分别保存，提交者是教师不等于所有批注均出自教师。

配置中的路径都已填写，不填Key；凭据不属于配置结构。换学生时需填写学生目录、文件在仓库中的绝对路径和已核实的学生版本revision。

结果目录：`D:\svn_agent\data\pipeline_runs\new_batch_<时间>`。

- `run.json`：统一状态、配置和代码哈希、各阶段输出及费用。
- `export`：SVN调用尝试、原始日志、导出原件、来源清单。
- `extract`：全部批注及锚点、原文、原始XML和图片附件。
- `candidates`：实际输入选择/覆盖、原响应、用量、候选规则及证据引句；不会启用规则。
- `check`：正文第一人称候选、大纲层级和XML表格线索。
- `report.md`：阶段报告及复核待办。

```powershell

```

`resume --run-dir` 核对代码、配置和完成步骤的附件哈希，跳过完成阶段；只能在阶段边界安全续接。已经开始或失败的阶段不会自动重试，避免重复付费或重复导出。此时保留日志，先定位问题，另做明确恢复。旧DOC会保留原件并返回 `needs_conversion`，不能通过跳过DOC冒充提取成功；既有转换核验工具仍可单独使用，尚未接入新通用流程。
